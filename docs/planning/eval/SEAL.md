## Pre-registered handling for H-b (decided before any model run)
- **Headline input = `nocomment/` variant.** 9 of 12 fixed files carry the fixer's own explanation of the cause in comments; feeding them would leak the answer. Original-with-comments scores are reported only as a secondary number.
- **Contamination check:** the obfuscated twin used for the original-vs-obfuscated comparison must be generated from the `nocomment/` variant with the sealed `obfuscate.mjs` before the first model call; its manifest hash is appended to this file in the same commit that precedes the run. If nocomment − obfuscated accuracy > 15 points, the obfuscated score becomes the headline.
- **Same-family risk:** 6 of 12 fix commits carry a Claude co-author trailer (`ai_attributed_commit`). Scores are reported separately for those 6 and the other 6.
- **Coverage limit:** H-b covers 3 of the 8 categories (RAW_BODY_ALTERED 6, EVENT_TYPE_DROPPED 2, OTHER_CODE_CHANGE 4). A_b is reported with this limit stated.
- `src/` upstream clones are not part of the sealed set.

## Pre-registered additions (2026-10-22, before any sealed run)
- **Confidently wrong (CW)** is counted as `shownWrong`: an answer that passed both code checks and would have reached a screen, yet names the wrong category (the harness's `shownNotRight`, which also counts a right category with wrong lines, is reported beside it and decides nothing). The product has no confidence field, so this is stricter than a high-confidence filter. CW is taken on H-a, as the mean over runs per case.
- **Readings of plan 6.7 that the plan leaves open** are fixed in the header of `eval/harness/verdict.ts` before any run: accuracy is by category (category-and-pointer is printed beside it); runs are averaged within a case, so N is the number of cases; "H-b 8건 이상" is the number of H-b cases, not the number right; "model ≤ B2" is read on H-a, a tie being RED; the twin's score replaces A_b only when the original and the twin differ by strictly more than 15 points.
- **Memorisation probes** (plan 6.5 item 3) are not run. The contamination check is the obfuscated twin of the H-b `nocomment/` variant, whose manifest hash is added as a row above before the first model call; if the original and the twin differ by more than 15 points, the twin's score is the headline A_b.
- **Exclusions** after the owner's audit of H-a labels: case ids are listed in this file with a reason and passed to the harness as exclusions; no file in a sealed folder is deleted or changed.
- **Transport failures** (timeout, network, 429, 5xx): the harness re-runs the same request at most twice and records first-attempt failures; a case that still fails is scored as not diagnosed and listed with its failures. Unreadable or empty answers are not re-run.
- **The verdict** (plan 6.7, three tiers) and Wilson 95% intervals on N cases are computed by `eval/harness/verdict.ts` from `results.json`; the script is committed before the first call. Scores are reported separately for the 6 H-b commits with a Claude co-author trailer and the other 6.

## Label audit, file shapes and derived sets (2026-10-26, before any sealed run)
- **Label audit.** The owner chose not to audit the H-a labels. A separate Claude agent (a fresh context started from the build session, given the category definitions and the symptom table, not the prompt, the baselines or the development runs) checked the 36 H-a labels, not a sample. Mechanical check, 36/36: category among the 8; category consistent with the symptom class under C2; cited file in the diff headers; each cited line a changed line of diff.patch by text and line number; the before/after trees differ exactly where the diff says. Judgment check (does the cited changed line do what the category's definition says): 35 right, 1 ambiguous, 0 wrong. The build session saw case ids, verdicts, one-line reasons and hashes only. The same mechanical check passed 12/12 on H-b `nocomment/`.
- **Exclusion:** `ha-35` (labelled EVENT_TYPE_DROPPED). The cited lines rename handler methods; the line that makes the dispatch miss them is unchanged, so EVENT_TYPE_DROPPED and OTHER_CODE_CHANGE fit about equally. It is left out by `--cases` listing the other 35 ids; nothing in a sealed folder is changed. Five labels were kept with a noted second reading (ha-04, ha-10, ha-13, ha-21, ha-24); they count as labelled.
- **File shapes.** The sealed sets were written before the harness (2026-10-19, 03:56Z and 04:37Z against 18:40 KST) and in their authors' shapes: H-a keeps its cases under `cases/<id>/`, its `symptom.json` under the key `symptom`, and cites lines by number with the text beside; H-b keeps each variant under `cases/<id>/<variant>/`, cites `{file, side, line, text}` objects and has no symptom file; B2 is a command-line program (`node b2.mjs <case-dir>`, one JSON line out) with no export. The frozen harness (`eval/harness/case.ts`) reads `<set>/<id>/` with `symptom.json {class}` and `label.json {category, file, lines: [text]}`, and `run.ts` imports a `--b2` module. The frozen files are not changed. Instead:
  - `eval/harness/convert-sealed.ts` (committed with this section) writes a derived set per sealed set: `before/`, `after/` and `diff.patch` copied byte for byte; `symptom.json` = `{class, symptom}` (one value under both keys; `symptom` is the key B2 reads); `label.json` = the category, the cited after-side texts as `lines`, the cited before-side texts as `altLines` (the scorer accepts either half of a modified line), the cited file and any other cited file as `altFiles`, and the tags `mix` and `stack` (H-a) or `ai_attributed_commit` and `stack` (H-b). The authors' notes, decoy lists and bug descriptions are not copied. Each cited text must be a changed line of the copied diff, or the script stops. Each derived set gets a MANIFEST.sha256 in the sealed format and a row below. Anyone with the sealed sets can re-run the script and compare the hashes.
  - **H-b symptom classes** (the set has none) are assigned before the run: for the 8 mechanism cases, the class C2 implies for the labelled category (RAW_BODY_ALTERED → all_401, EVENT_TYPE_DROPPED → 2xx_but_books_unchanged); for the 4 OTHER_CODE_CHANGE cases, the auditor agent chose the class from the commit message and the set's one-line bug description, and the four came out `other` (mixed or error responses; the basis for hb-82a0002c is weak). Under `other`, C2 leaves two categories (OTHER_CODE_CHANGE, NOT_IN_DIFF), so those four are a two-way choice; A_b is also reported on the 8 mechanism cases alone.
  - **Twin.** The sealed `obfuscate.mjs` reads two label fields that the sealed `scrub_comments.mjs` removes, so it cannot run on `nocomment/`; the sealed `obf/` folders were made from the originals, with the fixer's comments, and are not the twin. The twin is made by the two sealed scripts in the other order: obfuscate the original (default seed), map the comment-line file paths in the label through the obfuscator's own `map.json`, then scrub. Checked on the 12: the number of removed fix-comment lines equals the sealed `nocomment/` record, the diff line counts and the good-side file line counts equal `nocomment/`, each label line is a changed line, the paths are the obfuscated ones; a second build from scratch is byte-identical. The scripts are unchanged.
  - **B2** is run by `eval/harness/b2-run.ts` (committed with this section) as the program it is, on the derived H-a cases, through the same seal and freeze gate as `run.ts`; its cited line numbers are turned into the lines' text and scored by the frozen `score.ts`; the rows are merged into a copy of the model's results as `perCase[].B2` for `verdict.ts`. The sealed `b2.mjs` is not changed. B2 knows three symptom classes and exits on `other`, so it is not run on H-b (the verdict uses B2 on H-a only). Being deterministic, it was already run on the staging copy of the derived H-a set while the conversion was checked (2026-10-26, before this commit); the sealed run recomputes the same rows.
  - Keyword-free subset: the H-a tag `mix=keywordless` (`verdict.ts --kf-tag mix=keywordless`). H-b split: the tag `ai_attributed_commit` (6 true, 6 false). Runs: `--runs 3 --max-usd 6` per set, four workers; the derived sets are run with `--sealed <name>` after this commit.
